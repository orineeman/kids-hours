# בקרת אינטרנט לילדים — WhatsApp Web ואתרים נוספים

מערכת שרצה על מחשב הילדים (Windows). כל אתר שמוגדר ברשימה **חסום כברירת מחדל**;
ההורה נכנס ללוח בקרה בדפדפן (מכל מחשב, כולל מרחוק) ומעניק גישה זמנית ל-X דקות —
לאחר מכן האתר נחסם אוטומטית מחדש. המערכת גם רושמת דוח של כל הדומיינים שהמחשב
ניגש אליהם.

## ארכיטקטורה

- **Cloudflare Worker + D1** (`cloud/`) — מקור האמת: רשימת האתרים, הגרנטים,
  וחשבון ההורה. גם משגש את **לוח הבקרה** עצמו, כדי שההורה יוכל להיכנס מכל
  מקום (טלפון, מחשב אחר) בלי שום תלות במחשב הילדים באותו רגע. ראו
  `cloud/README.md` להתקנה.
- **סוכן סנכרון מקומי** (`src/cloudSync.js`) — רץ על מחשב הילדים, מסתנכרן עם
  הענן כל כמה שניות דרך HTTPS רגיל (פורט 443, לא Tunnel): שולף מצב
  אתרים/גרנטים עדכני למטמון מקומי, ודוחף יומן DNS שנצפה. **אם החיבור לענן
  נופל — האכיפה המקומית ממשיכה מהמצב האחרון שהיה ידוע, לעולם לא "נפתחת"**;
  ופקיעת גרנט נבדקת מול חותמת זמן מוחלטת, כך שהיא עובדת גם בלי רשת.
- **DNS resolver מקומי** (`src/dnsServer.js`) — כל שאילתת DNS מהמחשב עוברת
  דרכו. קורא מהמטמון המקומי בלבד (אף פעם לא מחכה לרשת בנתיב תשובת ה-DNS):
  אם הדומיין ברשימת "האתרים המנוהלים" וללא גרנט פעיל — מחזיר NXDOMAIN. אחרת
  מעביר לשרתי DNS ציבוריים ומחזיר את התשובה האמיתית.
- **Windows Firewall דינמי** (`src/firewall.js`) — בנוסף לחסימת ה-DNS, כל IP
  אמיתי שנצפה עבור אתר חסום נחסם גם ברמת ה-Firewall. זה מה שסוגר גם session
  שכבר פתוח, וגם מונע גישה ע"י הקלדת כתובת IP ישירה (עוקפת DNS).
- **עמוד מצב מקומי** (`src/status.js`, `http://localhost:8080`) — קריאה
  בלבד: זמן סנכרון אחרון, מטמון נוכחי, יומן DNS מקומי. בלי login, בלי כתיבה
  — לא תחליף ללוח הבקרה בענן.

> גרסה קודמת של הפרויקט הריצה את לוח הבקרה מקומית על מחשב הילדים וחשפה אותו
> דרך Cloudflare Tunnel. זה הוחלף (ראו היסטוריית git) כי `cloudflared` דורש
> פורט יוצא 7844 שהיה חסום ברשת הבית — הענן עוקף את זה לגמרי כי הוא רק צריך
> HTTPS רגיל.

## התקנה — מחשב הילדים

### 0. הקמת הענן (חד-פעמי, לפני ההתקנה על מחשב הילדים)

ראו `cloud/README.md`: פריסת ה-Worker/D1, הגדרת סיסמת הורה, ויצירת **Device
Token** אחד למחשב הילדים (`npm run device:create` בתוך `cloud/`). תצטרכו את
הטוקן הזה בשלב הבא.

### 1. קובץ התקנה (מומלץ)

יש מתקין Windows מוכן (`KidsNetControl-Setup.exe`) שעושה את כל השלבים
הבאים אוטומטית. ה-Node.js וכל חבילות ה-npm כבר ארוזים **בתוך** קובץ
ההתקנה עצמו (נבנים מראש ב-CI) — ההתקנה בפועל על מחשב הילדים לא נוגעת
באינטרנט בכלל מלבד הסנכרון השוטף עם הענן (HTTPS רגיל).

1. הורידו את הקובץ העדכני מדף ה-Releases של הפרויקט ב-GitHub (release בשם
   **installer-latest**), על מחשב הילדים.
2. הריצו אותו לחיצה ימנית → **Run as administrator**.
3. באשף: בחרו תיקיית התקנה, הזינו (אופציונלי) את **שם חשבון המשתמש של
   הילד** בוינדוס, והדביקו את **Device Token** שנוצר בשלב 0.
4. לחצו Install וחכו — ייפתח חלון PowerShell שמריץ את כל השלבים (שירות
   Windows, הקשחה, כתיבת הטוקן, הורדת הרשאות מחשבון הילד) ומדפיס סיכום
   בסוף. יומן מלא נשמר ב-`install.log` בתוך תיקיית ההתקנה.
5. אם משהו נכשל — הסיכום בסוף יגיד בדיוק אילו שלבים דורשים בדיקה ידנית;
   אפשר להריץ את המתקין שוב בבטחה (idempotent) אחרי שמטפלים בבעיה.

להסרה: לוח הבקרה של Windows → הוסרת תוכניות → KidsNetControl.

### התקנה ידנית / שלב-אחר-שלב (למתקדמים, או לדיבאג)

#### דרישות מוקדמות
- Node.js (גרסה 18 ומעלה) מותקן על מחשב הילדים.
- חשבון הילד במחשב מוגדר כ-**Standard User** (לא Administrator) — קריטי, אחרת
  כל ההקשחה חסרת ערך כי אפשר לעקוף אותה בקלות. את הפרויקט וההתקנה יש לבצע
  מחשבון Administrator נפרד.

#### 1. התקנת החבילות
```powershell
cd path\to\whatsapp-kids-hours
npm install
```

#### 2. טוקן המכשיר
```powershell
New-Item -ItemType Directory -Force -Path data | Out-Null
Set-Content -Path data\device-token -Value "<הטוקן מ-cloud/README.md>" -NoNewline
```

#### 3. בדיקה ראשונית (לפני הפיכה לשירות)
```powershell
node src\index.js
```
פלט צפוי: `DNS resolver listening on :53` ו-`Local status page listening on
http://127.0.0.1:8080`. אם `data/device-token` תקין, אין שום שגיאת
`cloudSync` ביומן.

> שימו לב: כברירת מחדל השרת מנסה להאזין ל-DNS על פורט 53, שדורש הרשאות
> Administrator ב-Windows. הריצו את הבדיקה הזו מ-PowerShell **כ-Administrator**.

#### 4. התקנה כשירות Windows (רץ תמיד, גם בלי login, עם auto-restart)
מ-PowerShell **כ-Administrator**:
```powershell
node install\service-install.js
```
זה יוצר שירות בשם `KidsNetControl` שרץ תחת SYSTEM, עולה עם המחשב, ומוגדר
להתאושש אוטומטית מכל קריסה. להסרה: `node install\service-uninstall.js`.

#### 5. הקשחה נגד עקיפה
מ-PowerShell **כ-Administrator**:
```powershell
powershell -ExecutionPolicy Bypass -File install\harden.ps1
```
הסקריפט מבצע בבת אחת: הגדרת DNS מקומי, כיבוי Chrome Secure DNS, חסימת
התקנת תוספי Chrome, חסימת DNS/DoH חיצוני ב-Firewall, ונעילת הרשאות על
תיקיית ההתקנה (כולל `data\` בנפרד — שם נמצא טוקן המכשיר). אפשר להריץ שוב
בבטחה בכל עת (idempotent).

## בדיקות מומלצות אחרי ההתקנה
- אתחול מלא למחשב → לוודא שהשירות עולה לבד ושהחסימה פעילה כברירת מחדל.
- מחשבון הילד: לנסות לשנות DNS / להתקין תוסף כרום / להקליד IP ישיר של וואטסאפ
  → לוודא שכל ניסיון נחסם.
- מלוח הבקרה בענן: להעניק 2 דקות לוואטסאפ, לוודא שנפתח בפועל (תוך כמה שניות
  — לפי תדירות הסנכרון), ולוודא שנחסם מחדש לבד אחרי הזמן.
- לוודא אילו דומיינים וואטסאפ ווב טוען בפועל (יכול להשתנות עם הזמן), ואם יש
  חדשים — להוסיף אותם מלוח הבקרה.
- לנתק זמנית את האינטרנט במחשב הילדים ולוודא שהחסימה/הפתיחה האחרונה נשארת
  בתוקף (לא "נפתחת" בגלל אובדן חיבור לענן).

## מגבלות ידועות
מכשירים אחרים (טלפון, טאבלט, מחשב אחר) לא מכוסים ע"י המערכת הזו; עקיפה ברמת
אתחול (Safe Mode / USB חי) דורשת הגנת BIOS/UEFI נפרדת שלא כלולה כאן.
